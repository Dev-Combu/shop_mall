## 🗺️ 1. 프로젝트 구조 개요 (Overall Structure)

본 프로젝트는 **관심사 분리(Separation of Concerns)** 원칙을 따르며, UI 로직(`views/`), 비즈니스 로직(`viewmodels/`, `services/`), 데이터 모델(`models/`) 등이 명확하게 분리되어 있습니다. 핵심 흐름은 View ➡️ ViewModel ➡️ Service/Model 의 파이프라인을 따릅니다.

## ✨ 2. 디렉토리별 상세 역할 분석 (Directory Deep Dive)

### 📂 `views/`
*   **역할:** 사용자 인터페이스(UI)를 구성하는 화면 단위의 코드들이 모여 있습니다. (View 계층).
*   **주요 파일 및 예상 기능:**
    *   `home.dart`: 앱 메인 랜딩 페이지.
    *   `product.dart`, `category.dart`, `search.dart`: 핵심 탐색 경로별 화면.
    *   `my_page.dart`: 사용자 개인화 영역 (로그인, 마이페이지 등).
    *   `cart.dart`: 장바구니 기능 UI.
    *   `share/`: 공유 기능을 위한 레이아웃을 정의합니다.

### <0xF0><0x9F><0x97><0x82>️ `viewmodels/` (상태 관리)
*   **역할:** 화면(View)이 필요로 하는 **데이터의 상태와 로직 처리 흐름**을 담당합니다. UI가 데이터를 직접 조작하지 않도록 막아주는 중요한 역할을 합니다.
*   **주요 파일 및 예상 기능:**
    *   `bottom_nav_viewmodel.dart`: 앱 전역적인 네비게이션 상태를 중앙에서 관리하는 핵심 모델로 보입니다.

### 💾 `services/` (데이터 접근 및 비즈니스 로직)
*   **역할:** **외부 시스템(API 서버 등)과 통신**하고, 실제 데이터를 가공하며 복잡한 업무 규칙을 실행합니다. 
*   ⚠️ **주의사항:** 현재 목록상에는 오타(`servies`)가 있는 것으로 보입니다. 이 폴더에는 API 클라이언트나 비즈니스 로직 레이어가 위치해야 합니다.

### 🧱 `models/` (데이터 구조체)
*   **역할:** 앱 전반에서 사용되는 **모든 데이터의 표준화된 틀(클래스)** 을 정의합니다. 이들은 단순히 데이터를 담고 있을 뿐, 로직을 가지지 않습니다.
*   **주요 파일:**
    *   `user.dart`: 사용자 정보 구조 정의.

### 🎨 `config/` (설정 및 기반 요소)
*   **역할:** 앱 전반에 걸쳐 일관성을 유지하기 위한 **공통 설정값, 테마, 라우팅 규칙**을 중앙 집중 관리합니다.
    *   `theme/`: 공통 색상(Colors), 폰트(Typography) 등 디자인 토큰을 정의하는 곳입니다. (`theme.dart`)
    *   `router/`: 화면 간 이동 경로를 미리 정의하여 관리함으로써, `main.dart`가 깔끔하게 유지되도록 합니다.

## ✅ 3. 아키텍처 기반 개선 및 권장 사항 (Recommendations)

1.  **폴더명 통일성:** `services/servies` 폴더명의 오타를 반드시 수정해야 합니다.
2.  **Layer 분리 검토:** 만약 비즈니스 로직이 매우 복잡하다면, `services/` 외에 별도의 **'domain/' 또는 'usecases/'** 디렉토리를 추가하여 UseCase 패턴을 적용하는 것을 고려해볼 수 있습니다.
